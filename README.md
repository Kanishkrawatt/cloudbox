# CloudBox

Personal cloud storage: upload images and files, keep them in folders, share
them with links that expire.

## Local setup

```bash
pnpm install
cp .env.example .env.local   # Firebase + Cloudinary values
pnpm dev                     # http://localhost:3000
pnpm test                    # unit checks
```

### Where things live

| Concern            | Service                                             |
| ------------------ | --------------------------------------------------- |
| Sign in / sessions | Firebase Auth                                       |
| File metadata      | Firestore                                           |
| File bytes         | Cloudinary                                          |

Firebase Storage is **not** used: since September 2024 Cloud Storage for
Firebase rejects every request on the no-cost Spark plan (HTTP 402), so uploads
go to Cloudinary instead, free plan, 25 credits/month (~25 GB storage or
bandwidth). Uploads are signed server-side by `/api/cloudinary/sign`, which
verifies the caller's Firebase ID token first, so the API secret never reaches
the browser and each user can only write into their own folder.

### Expired share links

`/api/deleteExpiredData` purges Smart Shares past their expiry. It walks every
user, so it is gated on `CRON_SECRET`; call it on a schedule:

```bash
curl -H "Authorization: Bearer $CRON_SECRET" https://<host>/api/deleteExpiredData
```

Expiry is also enforced when a link is opened, so a share stops working on time
even if the job has not run yet.

### Sort by face

Smart Share can group a share's photos by who appears in them, using the
companion service at https://github.com/Kanishkrawatt/Sort-Image-by-Face.

Set on CloudBox (`.env.local`, and on Vercel):

```
FACE_API_URL=https://server-yg89.onrender.com
FACE_API_KEY=<same value as API_KEY on the face service>
```

`FACE_API_KEY` is server-side only, never `NEXT_PUBLIC_`. Without it the feature
reports "not configured" and shares still work.

Set on the face service (Render dashboard):

```
APP_SECRET=<any passphrase>          # required: the server exits on boot without it
API_KEY=<same value as FACE_API_KEY>  # required: the API returns 503 without it
ALLOWED_IMAGE_HOSTS=res.cloudinary.com
COOKIE_KEY                            # generated by render.yaml, nothing to do
```

Images are sent as `w_800` Cloudinary derivatives: measured on the free Render
instance (512MB, 0.1 CPU), eight photos at `w_1600` killed the process mid-job,
while the same eight at `w_800` returned in ~46s. Raise `FACE_IMAGE_WIDTH` in
`utils/faceApi.ts` if the service moves to a bigger box.

Operational notes: the free Render instance sleeps, so the first request after
an idle period takes around 45 seconds. Batches over 15 images go through a job
queue whose results live in memory, so a 404 while polling means "resubmit",
not "failed".

### Themes

8 presets (Snow, Graphite, Midnight, Dracula, Nord, Forest, Solarized, Sunset),
picked from the sidebar gear or the profile page and remembered in
`localStorage`. Palettes live in `utils/contexts/theme.tsx`; add one by
appending a `preset(...)` entry and it shows up everywhere.

# CloudBox API Documentation

It is possible to use the API to create and manage the resources used by the application. The API is available at the following address: `/api`.
It is RESTful and uses the following HTTP methods:
`GET` `POST` `PUT` `DELETE`.

## Base URL

`https://cloudbox.kanishkrawatt.tech/api`

## Authentication

Authentication is required for accessing CloudBox API endpoints. You need to include an API key in the header of each request.

API requests must be authenticated using a token that can be obtained from [Here](/profile). The token must be sent in the `Authorization` header of the request.

```js
Authorization: Bearer <your_api_key>
```

## Endpoints
### 1. **Get Images**

Retrieves a list of images stored in CloudBox.

- **Endpoint**: `/getImages`
- **Method**: `GET`
- **Response**:
  - Status: 200 OK
  - Content: JSON array of image objects, each containing metadata about the image

### 2. **Get Files**

Retrieves a list of files stored in CloudBox.

- **Endpoint**: `/getFiles`
- **Method**: `GET`
- **Response**:
  - Status: 200 OK
  - Content: JSON array of file objects, each containing metadata about the file

### 3. **Delete Items**

Deletes a specific item from the storage.

- **Endpoint**: `/deleteItem`
- **Method**: `DELETE`
- **Parameters**:
  - `data: [itemurl]`: Url of the item to be deleted
- **Response**:
  - Status: 200 OK
  - Content: JSON object with a success message

### 4. **Delete Expired Data from Storage**

Deletes expired data from the storage.

- **Endpoint**: `/deleteExpiredData`
- **Method**: `POST`
- **Request Body**:
  - None
- **Response**:
  - Status: 200 OK
  - Content: JSON object with a success message
